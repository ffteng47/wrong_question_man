## 1. 核心裁决

### 1.1 双入口（App 是唯一统一壳）

```text
wrong_answer_client (Flutter)
│
├── A. 试卷作业上传（新增）          ──直连──→ exam-server /api/answer/*
│      选卷→多图→提交→任务列表→判题结果      （识别/定位/判题全在服务端，App 零智能）
│      错题由判题链路自动入 incorrect_question（A9），App 不手动转
│
└── B. 单题错题录入（升级现有）      ──直连──→ wrong_answer_server :9000
       拍照→ROI框选→异步识别→校正→提交       （MinerU+Qwen2.5-VL 本地流水线）
```

**边界冻结**：

1. `wrong_answer_server` **不实现** Paper Ingestion 的任何环节（不做试卷匹配、不做判题、不管坐标模板）。试卷链路的识别即使要用本地 Qwen，也走 exam-server 侧的 `localQwenProvider` 接口位（对方详设 §1.2 已预留，fail-closed），与本项目无关。
2. 入口 A 不经过 `wrong_answer_server`，两张皮互不感知，只在 App 首页并列。
3. **不做**：自动全卷切题、跨页题合并、App 端几何矫正（见 §2 裁决 #3）。

### 1.2 对外部设计方案的逐条裁决

原《商用级视觉录入升级设计》评审结论（两轮，第二轮已并入试卷链路事实）：

| 设计条目 | 裁决 | 说明 |
|---|---|---|
| P0-1 双入口收敛 | ✅ 采纳 | 按 §1.1 形态落地；"整套试卷"语义 = 判题链路而非多图错题堆 |
| P0-2 多图上传+质量检测+透视矫正 | ⚠️ **裁剪采纳** | 只留"拍照→相册(HEIC转JPEG)→排序→删除→批量上传"。**App 端不做任何几何/透视处理**：试卷链路坐标基准图是服务端 `normalized_path`（题面详设 §3.3 硬约束1），App 端改像素会导致题框整体错位，有害 |
| P0-3 ROI 编辑器升级 | ✅ 采纳（增量） | 8 手柄已有（盘点 #2），补缩放/平移/双指；坐标系**全 App 统一 0~1000 归一化**（§3.1），与试卷链路题框层共用同一换算组件 |
| P0-4 题目/答案双区域 | ⚠️ **仅限错题链路** | 试卷链路已反向冻结：v2.2 删除 `answer_region`、裁切图 UI 退役。**禁止**把双区域带入 `/api/answer/*` 的任何展示。错题链路内 P0 只加 `answer_region` 的 **bbox+裁切图**；手写答案**识别**能力属 P1（现有链路对手写无任何产出） |
| P0-5 识别结果确认页 | ✅ 已存在 | `preview_screen.dart` 即是，不重建；P0 只加"左图右文联动"（§5.3） |
| P0-6 识别任务状态机 | ✅ 采纳（错题链路） | 真实缺口（盘点 #8）。**状态名对齐试卷链路枚举**（§4.2），两套后端对外语义一致，App 一份映射代码 |
| P0-6'（试卷链路） | ✅ 服务端已有 | `paper_uploads.status` 11 态枚举已冻结，App 只做展示映射 + 30s 轮询 + 终态停轮（§5.4），socket 第一版不做 |
| P1-1 Provider 路由 | ⏸ 延后 | 本地现在只有 MinerU+Qwen 一家，现有 fallback（盘点 #4）就是"路由"。等接第二家 OCR 再抽接口；当务之急是清理 `qwen_client copy*.py` 复制文件（真技术债） |
| P1-2 快速OCR/数学/手写分流 | ⏸ 延后 P1 | 依赖 Provider 接口，同上 |
| P1-3 识别证据链 RecognitionRun | ✅ **提前到 P0** | 成本极低、三份 audit 文档证明刚需；错题链路先以 JSON 落盘起步（§4.3），不建表 |
| P1-4 分项置信度+自动通过门槛 | ❌ **驳回（现状）** | MinerU content_list **无置信度**（解析处 `score=None` 注释明说）、Qwen VLM 自报 confidence 未标定（试卷链路详设 v1.4 同款警示）。在拿到校准数据前，UI 可显示"质量提示"（§2-3 简单检测），**不做任何自动放行逻辑** |
| P2-1 智能框选 | ✅ 已上线 | 盘点 #1，跳过 |
| P2-2 视觉资产链 | ⚠️ 简化采纳 | 错题链路用 `image_id/record_id/recognition_id` 三级 ID 即可（§4），不建 Document/Page 全套实体 |
| P2-3 Badcase 闭环 | ⏸ 延后 P2 | 第一版只存 `original AI 输出 + corrected 最终值` 配对（RecognitionRun 天然覆盖一半），不建 benchmark 平台 |
| P2-4 录入工作台 UI | ⚠️ 改判 | 手机竖屏不做桌面式左右分栏；形态 = 确认页"左图右文联动"（§5.3） |

**一句话**：骨架（双入口、状态机、证据链、双区域）采纳约七成；驳回的是拿假置信度做自动决策、把无能力支撑的手写识别塞进 P0、以及一切与试卷链路冻结契约相抵触的"带入"。

## 2. 单题错题链路：升级设计

### 2.1 流程（升级后）

```text
拍照/相册
  ↓
本地预览 + 轻量提示（长边<1024 或 Laplacian 方差过低 → 建议重拍，可强行继续）
  ↓
上传 POST /upload（秒回：image_id + 版面 blocks + 尺寸）        ← 同步阶段保留，只含预处理与轻量存储
  ↓
后台任务 T-parse：MinerU 全页版面解析 → preview_blocks 推送        ← 新增异步
  ↓
ROI 编辑器（缩放/平移/双指/8手柄，输出 0~1000 归一化 bbox）
  ↓
POST /extract（秒回 task_id）→ 轮询 GET /tasks/{id}
  ↓
任务 T-extract：ROI筛选→Qwen语义→(空则Vision fallback)→Asset裁切 → recognized
  ↓
确认页（左原图+题框/答案框联动，右题干/作答可编辑）
  ↓
POST /save（用户校正后的完整 record；同时落 corrected 配对）
```

> 说明：现有 `/upload` 同步跑全页 MinerU 是单题链路最慢的一步（分钟级风险），异步化后首屏只剩"存储+EXIF"，秒回。

### 2.2 ROI 编辑器（Flutter）

- 现 `RoiSelector` 重构为通用组件 `RegionEditor`：
  - 输入：图片 + `List<Region>{bbox0_1000, label, editable}`；
  - 手势：双指缩放/平移（InteractiveViewer 包裹 + 变换矩阵），框的 8 手柄在**图像坐标系**（0~1000）里命中测试，屏幕坐标只做渲染换算；
  - 输出：0~1000 归一化 `[x1,y1,x2,y2]`，**服务端不再需要 `_remap_roi`**（保留做一版兼容：入参带 `coord_space: "0_1000"` 字段则跳过换算）。
- 试卷结果页题框层（§5.5）复用同一渲染换算（只读模式）。

### 2.3 质量检测的边界

- App 端仅做**提示级**：分辨率、模糊（`image` 包已有依赖可做简化拉普拉斯，或仅提示重拍引导文案），不阻断、不修图。
- 服务端 `preprocess.py` 已有处理位，透视/纠偏**继续不做**（MinerU 版面解析对轻度倾斜容忍 + Vision fallback 兜底，投入产出不成立）。

## 3. 数据模型变更（wrong_answer_server）

### 3.1 坐标口径统一（对齐试卷链路 v2.2 ③ 冻结口径）

| 阶段 | 口径 |
|---|---|
| 传输/存储 | **一律 0~1000 归一化 `[x1,y1,x2,y2]`**，新增字段 `coord_space: "0_1000"` |
| 兼容 | 无 `coord_space` 的旧客户端请求按原图像素走 `_remap_roi`（一版后下线） |

### 3.2 `WrongAnswerRecord` 变更（schema.py）

```python
class Region(BaseModel):
    bbox: list[float]            # 0~1000 归一化
    coord_space: str = "0_1000"
    image_path: Optional[str] = None   # 裁切图（rois/ 下）
    text: Optional[str] = None         # 该区域的识别文本
    confidence: Optional[float] = None # 可为 None——无校准即诚实留空

# Source.user_selection → 替换为：
question_region: Optional[Region] = None   # 题干印刷区（原 roi_bbox 语义）
answer_region:   Optional[Region] = None   # 学生作答区（P0 只存 bbox+裁图，识别留 P1）
```

- 手写答案识别**不在本期**：`answer_region.text` 允许为空，确认页作答框支持用户手输。
- `recognized_text` 多空数组语义**不引入**（那是试卷链路的契约，单题链路一框一答，保持简单）。

### 3.3 RecognitionRun 证据链（P0，JSON 落盘不建表）

```text
storage/runs/{record_id}/{run_id}.json
{
  run_id, record_id, image_id,
  stage: "parse" | "extract" | "vision_fallback",
  provider: "mineru" | "qwen_semantic" | "qwen_vision",
  model_version, prompt_version,
  roi: [x1,y1,x2,y2] (0~1000),
  raw_output, normalized_output,
  latency_ms, created_at,
  corrected_output: null            ← /save 时若用户改过，回填最终值
}
```

回答"这道题为什么识别错"时按 record_id 回放整条链。`mineru_client.py` 里补 `score` 透传（MinerU vlm 引擎有则存，无则 null——**不得**拿 null 当高置信）。

## 4. 错题链路服务端 API 与状态机

### 4.1 端点（新增 tasks.py，兑现 README 承诺）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/upload` | 改为**秒回**：存图+EXIF → 建任务 → 返回 `{image_id, task_id}`；`preview_blocks` 移入任务结果 |
| POST | `/api/v1/extract` | 建任务秒回 `{task_id}` |
| GET | `/api/v1/tasks/{task_id}` | 状态+进度+结果（完成时返回原 `UploadResponse`/`ExtractResponse` 载荷） |

任务存储：进程内 dict + `storage/tasks/{task_id}.json` 落盘（重启可查终态）。**不引入 Redis/Celery**——单机单用户量级，`--workers 1` 前提下 asyncio 任务表足够；写不出这个约束的评审意见一律按"过度设计"处理。

### 4.2 任务状态（命名对齐 paper_uploads.status）

```text
created → uploaded → processing → recognized → failed(retry→processing)
                         ↓
                    submitted（/save 后关闭）
```

进度映射（App 一份枚举同时覆盖试卷链路 §5.4）。异常恢复：`processing` 超时（parse 10min / extract 5min）由惰性清扫置 `failed`，客户端可 `POST /tasks/{id}/retry`。

## 5. App 端试卷作业链路（对齐题面详设 v2.4 冻结契约，只此引用不重复设计）

### 5.1 新增页面

```text
home_screen（双入口）
├── 错题拍照（现有链路）
└── 试卷作业
    ├── paper_pick_screen    选卷：GET /api/answer/papers/search?code=
    ├── paper_capture_screen 多图：拍照直出JPEG；相册选图强制转码HEIC→JPEG（题面 §1.4(a) 缺口的App侧规避）
    ├── paper_task_list_screen 我的任务：GET /api/answer/uploads
    └── paper_result_screen    任务详情+判题结果（A11b 的 Flutter 复刻）
```

### 5.2 上传

`POST /api/answer/uploads` multipart `{paper_code?, files[]}`；上传前本地校验：≤20MB/张、≤20 页（`ANSWER_UPLOAD_MAX_*` 口径）。成功即建任务，**页面立即可离开**。

### 5.3 详情与轮询

- `GET /api/answer/uploads/:id` → `upload + pages[] + results[]`（学生安全视图，题面 §4.1）。
- 轮询 30s；`unmatched` 行服务端已滤除，App 不处理；`ambiguous` 行 `question_id=null` 但题干/框照发，展示为"需要老师确认"折叠态（`grade: pending_teacher` 时**不显示分数与原因**——需求 #15 折叠在服务端已完成，App 照渲染即可）。
- 判题四色：correct绿/wrong红/partial橙/pending_teacher黄。

### 5.4 状态进度映射（与错题链路共用枚举）

`paper_uploads.status` 11 态直读；终态集 `{等待人工确认, 部分完成, 完成, 处理失败}` 停轮询；进度沿用 Web `PROGRESS_BY_STATUS` 镜像值（App 内硬编码同一张表，改动须与 Web 同步登记）。

### 5.5 图上题框层

- 图取 `GET /api/answer/pages/:pageId/image?type=normalized`（**带 cookie**，Dio 拦截器已有；404/403 按缺图处理）。
- `question_region` 为 0~1000 归一化 → `Positioned(left:x1/10%, top:y1/10%, width:(x2-x1)/10%...)` 百分比定位（题面硬约束2），**不做任何像素换算**、不切原图展示框（硬约束1：框只在校正图上渲染）。
- 交互仅"点框→右栏/底部抽屉联动"（题面口径：不做图上缩放拖拽）。
- 渲染组件 = `RegionEditor(readonly)`。

### 5.6 登录态

试卷入口要求 `role: student` 的 semecTeaching 会话；现有 `SemecTeachingApi` 复用，入口点击时未登录 → 跳设置页登录（沿用 home_screen 的提示模式）。

## 6. MinerU 本地化对两条链路的影响

| 链路 | 影响 |
|---|---|
| 错题（wrong_answer_server） | **无新增工作**——本来就设计为与 MinerU/vLLM 同机（§0-11），GPU 恢复只是解除运行前提 |
| 试卷（exam-server） | 云端 `deepseek-flash` 仍是当前 Provider；GPU 恢复使 `localQwenProvider`（MinerU+Qwen 本地）具备启用条件。**属 semecTeaching 侧变更，不在本项目范围**，仅在此登记事实，防止两边文档互相"等对方" |
| 资源冲突 | 试卷链路 MinerU（exam-server-python 侧）与错题链路 MinerU（本服务器 mineru-api）**若是同一实例**，分钟级整卷解析会挤占单题解析——上线前压测确认，必要时错开 GPU 服务或加队列（登记为风险 R2） |

## 8. 开发顺序（里程碑）

```text
M1 错题链路异步化 + 坐标统一（P0 核心）
   ├─ server: tasks.py 状态机、/upload /extract 异步化、coord_space、超时清扫

   └─ client: 两处硬编码 IP 迁配置

   ├─ server: question_region/answer_region、RecognitionRun 落盘、/save 回填 corrected
   └─ client: 确认页左图右文联动、题框/答案框分别重识别入口
M3 试卷作业 App 端（独立并行可先行，纯客户端零服务端等待）
   ├─ answer API 方法组（search/uploads/tasks 详情/page image）
   ├─ 选卷→多图→提交→任务列表→轮询详情
   └─ 结果页题框层 + 底部抽屉联动
M4 P1 识别升级（依赖 M1 证据链数据积累）
   ├─ 手写答案识别（answer_region 裁图 → qwen_vision，先只做转写不做判对错）
```
